# REG-07 — утверждённый пакет и начало работы над макетом

**Продолжение:** UI-02–06 и [UI-07 — центр уведомлений](neurojurist-spectrum-ui07.md) реализованы синтетически в описанных границах. Согласованный [HYP-01](neurojurist-spectrum-priority-queue.md) меняет дальнейшую очередь: сначала P0 Documents → Chat → источники, затем P1/P2, административные расширения — P3. REG-07 сохраняется как утверждённая спецификация прав и scope; приоритизация не переопределяет DEC.

**UI-08 / P0:** [ревизия основного пути и первые исправления](neurojurist-spectrum-ui08.md) выполнены по HYP-01. Область workspace-поиска, восстановление собственного вопроса и статусы задач представлены синтетически; это не реальный retrieval и не полная приёмка P0. Далее — оставшиеся ветви P0, без расширения прав или подключения backend.

**UI-09 / P0:** [сбой поиска, большой контекст и неполное извлечение](neurojurist-spectrum-ui09.md) представлены в mock-маршруте. Качество версии и ограничения результата не расширяют ACL или grant-scope; демо-лимиты не объявляются production-квотами. Далее — покарточная сверка P0 по HYP-01.

Основание: пользователь подтвердил весь предложенный пакет словами **«Да, весь пакет, начинай»**. Это разрешение работать над UX/UI-макетом, не поручение подключать backend, реальные AI, почту или хранение клиентских файлов.

Этот документ имеет приоритет над остаточными вопросами REG-06 в связанных планах и карточках. Исходные 174 ID и архивные требования не переписываются. Подтверждение требований не означает готовность соответствующего интерфейса.

## Карта поверхностей

| Поверхность | Объект / изменяемость | Вход → результат → возврат |
|---|---|---|
| Главная | Доступные проекты и личная навигация | Вход → выбрать проект; быстрая задача сначала выбирает проект |
| Библиотека | Документы одного проекта | Проект → загрузка/поиск → карточка → библиотека с актуальными статусами |
| Загрузка | До 10 файлов, проверка каждого | Библиотека → валидация/дубликаты → обработка в проекте; можно уйти |
| Документ | Версия оригинала, просмотр; не Draft | Библиотека/источник → текст/страницы/версии → анализ или новый чат с явным контекстом |
| Анализ | Отдельный результат по версии документа | Готовый документ → риски → документ; VIEWER не запускает |
| Chat | Диалог одного проекта, PRIVATE/WORKSPACE | Проект/документ → выбранные материалы → задача → ответ → использованная версия/фрагмент |
| Research | Сохранённое исследование проекта | Вопрос/параметры → результат/источники → список или новый чат |
| Draft | Изменяемый текст, не оригинал | Список/Chat → редактирование/AI/Review → save/history/compare → повторное открытие |
| Участники / org | Membership отдельно от чтения | Проект/org → приглашение/передача/revoke → статус без раскрытия PRIVATE |
| Grant / аудит | Ограниченный scope и безопасные события | Отказ → запрос → независимое решение → TTL/revoke → история |

Общие состояния: loading, empty, no results, error/retry, read-only/forbidden/revoked; для документов дополнительно queue/extract/index/ready/OCR/error; для AI строго queued/running/succeeded/failed/cancelled/timed_out. Partial — свойство результата.

## Рабочий пакет UI-01

В работе: библиотека и карточка документа, демонстрационная загрузка/валидация/дубликаты, фоновые стадии, выбор контекста, связанный синтетический Chat и переход к версии источника. Состояние хранится только в памяти открытого макета и сбрасывается при перезагрузке. Реальный текст выбранных файлов не читается/не отправляется: показывается явно подписанный синтетический образец.

Покрытие и проверки UI-01 записываются ниже после выполнения; весь каталог не объявляется проверенным.

### Результат UI-01

Реализован связанный демонстрационный путь без обязательного демопереключателя:

1. Проект → библиотека → выбор файлов или синтетического образца.
2. Индивидуальная проверка PDF/DOCX/TXT, пустого файла, 25 МБ, 10 файлов; смешанный результат; дубликат пропустить/версия/копия.
3. Очередь → извлечение → индексация → готовность, либо OCR/error; повтор. Стадии продолжаются при уходе со страницы.
4. Просмотр текста DOCX/TXT, постраничный образец PDF, версии и метаданные, переименование/подтверждение удаления с ролевой проверкой.
5. Документ → новый PRIVATE-чат → явно выбранный контекст → вопрос → queued/running/succeeded. Продолжение и повторное открытие из списка проекта.
6. Использованные источники отдельно от выбора материалов → фрагмент/версия → открытие этой версии. Новая версия не подменяет источник старого ответа.
7. Правка вопроса/регенерация создают отдельную ветку; исходная история остаётся. При правке старого вопроса исходная версия контекста сохраняется явно; обычный следующий вопрос требует актуализировать изменившийся контекст.
8. Остановка сохраняет partial, если генерация началась; cancelled/failed/timed_out не выглядят полным успехом. Ошибка/тайм-аут выбираются в панели материалов как демо-сценарий, повтор сохраняет предыдущую попытку.
9. PRIVATE → WORKSPACE с отдельным предупреждением. Удаление источника закрывает зависимый исторический ответ целиком.
10. OWNER-only переименование проекта, EDITOR не удаляет чужое, VIEWER не загружает/не отправляет/не принимает AI-правки и не отменяет Review. Смена типа существующего проекта убрана из меню. На Главной быстрая задача выбирает проект, пустой список не оставляет чужих карточек внимания.

### Проведённые проверки

- `pnpm exec tsc --noEmit` — успешно после финальных исправлений.
- `pnpm build` — успешно. Предупреждение Vite: JS-чанк больше 500 КБ; production-оптимизация не была целью этого макета.
- `git diff --check` — успешно.
- `tests/ui01.browser.mjs` — **17 групп сценариев успешно**, без браузерных runtime-ошибок. Chromium, существующий preview `http://localhost:3000`; отдельный dev server не запускался.
- Проверены 1280/1440 px для библиотеки, просмотрены карточка и источник при 1280 px, узкое ограничение на 390 px. Полный keyboard-only/screen-reader аудит не проводился.
- Форматирование вызвано через `pnpm format` (oxfmt 0.2.0). Найден дефект установленного formatter: удаление разделителей в однострочных TypeScript type literals. Разделители восстановлены вручную; затем TypeScript и сборка перепроверены успешно. Повторное автоформатирование этих типов без проверки небезопасно.
- Неуспешные промежуточные проверки выявили дефект форматтера и блокировку ветвления вопроса по исторической версии; они исправлены. Финальный полный браузерный прогон выполнен без правок файлов во время него, чтобы hot reload не сбрасывал демонстрационное состояние.

Для повторения браузерного прогона нужен `playwright-core` и установленный Chromium. Зависимость использовалась из `/tmp`, зависимости приложения не менялись:

```sh
PLAYWRIGHT_MODULE=/tmp/neurojurist-browser/node_modules/playwright-core/index.mjs node tests/ui01.browser.mjs
```

### Ограничения и продолжение

Это не production-реализация: нет реальной загрузки/извлечения/индексации/AI/почты/auth/backend; диалоги и материалы сбрасываются при перезагрузке. Источники вымышлены, текст выбранного файла не читается. Клиентские ролевые проверки не доказывают серверную безопасность.

Следующий пакет: Research/Draft по REG-07, затем auth/участники/lifecycle/grant/аудит и дополнительные поверхности. Полная матрица покрытий и handoff 174 сценариев остаются в работе. Подтверждённые решения повторно не спрашивать.
