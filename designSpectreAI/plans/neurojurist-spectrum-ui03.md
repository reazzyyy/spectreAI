# UI-03 — вход, приглашения и участники

**Продолжение:** [UI-04 — передача владения/уход OWNER](neurojurist-spectrum-ui04.md) реализован синтетически и проверен; далее grants/аудит/удаление. Раздел «Продолжение» ниже сохраняет исторический срез UI-03.

Основание: пользователь **«поехали дальше»** после UI-02 и согласованной последовательности «вход, приглашения, участники → передача владения → организационная безопасность». Доработан синтетический UX/UI-макет, не production-auth. Backend, реальная почта, сессии/пароли на сервере и durable membership не подключались.

## Завершённые связанные пути

### Вход и первый доступ

- Меню профиля → выход → Login. Прямые маршруты `#/login`, `#/forgot-password`, `#/reset-password?token=…`, `#/invite?token=…`.
- Формы: email/пароль, валидация, показ/скрытие пароля, busy с защитой от повторной отправки, нейтральная ошибка неверных данных, ошибка сервиса и повтор.
- После каждого успешного входа/принятия приглашения **всегда Главная**: проверены 0, 1 и несколько доступных проектов, без возврата на прежний объект.
- Выход и истечение сессии скрывают защищённые экраны; browser back/hash не раскрывают их без нового входа.
- Истечение сессии принудительно прекращает доступ. Несохранённый Draft очищается до последней сохранённой рабочей копии; текст формы/пароль не восстанавливаются из небезопасного кэша. Добровольный выход использует существующий guard несохранённых правок.
- Восстановление: нейтральный ответ независимо от существования аккаунта → образец письма → одноразовая ссылка на 1 час → проверка нового пароля/подтверждения → Login → Главная. Истёкшую/использованную ссылку нельзя повторно применить.
- Публичной регистрации, самостоятельного создания первой Organization, SSO/MFA нет. Новый аккаунт создаётся только через действующее приглашение. Bootstrap первой организации остаётся внешней предпосылкой.

### Приглашение в Organization

- Owner организации: сотрудники → email → приглашение на 7 дней → образец письма → интерфейс получателя. Реальное письмо не отправляется.
- Новый пользователь задаёт имя/пароль; существующий подтверждает аккаунт **адреса приглашения**. Принятие подтверждает email и создаёт только org membership.
- Истечение, отзыв, повторное использование, запрос нового, повторная выдача и ошибка с сохранением email представлены. Новая ссылка отзывает прежние pending-ссылки этого адреса в данной организации.
- Срок токена повторно проверяется в момент выполнения, в том числе если приглашение истекло во время busy.
- Принятие не назначает TEAM-роль, не раскрывает PERSONAL и PRIVATE. Новый сотрудник видит пустую Главную, пока не назначен в проект.
- Переключатель доступных организаций — на Главной. Список проектов, недавние материалы, пины и справочники связей изолированы по организации. Данные справочника другой организации не предлагаются в создании проекта.

### Участники проекта

- Проект → «Участники» → список, поиск и фильтр OWNER/EDITOR/VIEWER.
- OWNER/уполномоченный org-администратор явно назначает **существующего сотрудника текущей Organization** в TEAM как EDITOR/VIEWER. Дополнительное второе приглашение в TEAM не вводится: назначение применяется явным действием управляющего; приглашение и принятие Organization остаются отдельным процессом.
- Смена EDITOR↔VIEWER — с подтверждением и объяснением последствий, ошибка/повтор без потери выбора.
- Отзыв членства TEAM — с подтверждением. Материалы и авторство остаются, PRIVATE-история не передаётся другим. Остальные проекты/членство Organization не изменяются.
- Единственного OWNER нельзя удалить или заменить обычным select роли. PERSONAL остаётся однопользовательским, смена типа проекта не добавлена.
- Org Admin может управлять TEAM membership через административные метаданные **без content-tabs и без чтения материалов**. Нельзя назначить себе membership/роль через этот интерфейс.
- В рабочих моделях учитываются текущий actor и org/project membership. EDITOR и VIEWER демонстрируются на одном проекте «Север», не на разных подставных наборах.
- PRIVATE-чаты фильтруются по неизменяемому ID автора; WORKSPACE становится общим только после ранее согласованного подтверждения. Удаление member не удаляет его историю; восстановленный доступ того же автора не меняет её ownership.
- Авторство документов/Draft привязано к `authorId`, не имени. Однофамилец с таким же отображаемым именем не получает права удаления чужого материала.
- Отмена AI разрешена инициатору/OWNER доступного контекста, не любому EDITOR. Перед выдачей фонового результата учитывается актуальное членство инициатора; потерявшие права задачи не считаются успешной выдачей.

## Демо-входы и ограничения

- Для сохранения уже построенного preview стартует демосессия Елены. Экран входа доступен через **меню профиля → Выйти** или прямой `#/login`.
- «Заполнить демоданные» и блоки «Демонстрационные сценарии» — явные средства демонстрации, не настоящие аккаунты. Вводить только тестовые данные. Пароли и токены находятся в памяти страницы и сбрасываются при перезагрузке.
- Меню профиля → «Смотреть как сотрудник»: Елена (org Owner и участник проектов по отдельным назначениям), Алексей (EDITOR в «Севере»), Дарья (VIEWER), Олег (Org Admin без content membership), принятые приглашённые.
- Организационная роль не заменяет Workspace-роль. Начальные доступы Елены/других демоаккаунтов заданы явными фикстурами. Существующее создание собственного проекта остаётся демонстрационным правом активного сотрудника; полноценная конфигурация org-политики создания не добавлена.
- Первая организация/Owner через bootstrap, org-revoke/увольнение, передача владения, ограниченный TEAM, grants, approvers, аудит и удаление проекта — **следующий пакет**, не объявлены реализованными этим UI.
- Это не доказательство серверного ACL, устойчивой аутентификации, реальной доставки почты или межбраузерной синхронизации.

## Проверки

- `pnpm exec tsc --noEmit`, `pnpm build`, `git diff --check` — успешно. Сборка сохраняет неблокирующее предупреждение Vite о JS-чанке >500 КБ; production-оптимизация вне цели макета.
- `tests/ui03.browser.mjs` — **21 группа успешно**, без браузерных runtime-ошибок: вход/ошибки/back, expiry без восстановления несохранённого текста, reset/одноразовость, tenant switch, новые/существующие приглашённые, revoke/reissue, членство/роли/ошибка, PRIVATE, сохранение материалов, Org Admin, PERSONAL, персональные пины, однофамильцы и истечение во время busy.
- `tests/ui01.browser.mjs` — **17 регрессионных групп успешно**.
- `tests/ui02.browser.mjs` — **20 регрессионных групп успешно**.
- Проверены desktop-ширины 1280/1440 для участников/организации и Login, просмотрены Login и Members. Отдельный браузерный smoke проверил пустой справочник связей другой организации и изоляцию созданного в ней проекта после повторного входа. Keyboard-only/screen-reader аудит не заявляется.
- `pnpm format` применён к новым auth/membership файлам, обновлённым моделям и тесту; после него TypeScript перепроверен. Старые однострочные type literals не переформатировались из-за известного дефекта oxfmt 0.2.0 (UI-01).
- В промежуточных прогонах уточнены неоднозначный selector пустого списка чатов и ожидание асинхронного результата перед сменой демоаккаунта. Модель не применяет запрос старого actor после его смены. Финальный полный прогон выполнен без правок файлов во время выполнения.
