# План: упрощение интерфейса «НейроЮрист Спектр»

## 1. Цель

Сохранить принятые шрифты (Golos Text + Noto Serif), палитру и общую концепцию, но убрать ощущение перегруженности. Результат: на каждом экране один главный объект внимания, меньше рамок, меток и одновременно видимых элементов, спокойный ритм и читаемые размеры текста.

## 2. Диагноз (по текущему коду)

1. **Прототипные элементы смешаны с продуктом.** Баннер «демо», переключатели состояний («Ответ / Генерация / Ошибка», «Результат / Загрузка / …»), блок пустого состояния прямо на главной. Пользователь не отличает продукт от инструментов показа.
2. **Слишком много визуальных контейнеров.** Секции в рамках, внутри рамок строки с рамками, карточки, бейджи. Единого «одного уровня» разделения нет.
3. **Слишком мелкий и разнородный текст.** Много размеров 9–11px, заглавные eyebrow-подписи почти везде, что создаёт шум.
4. **Слишком много бейджей и цветных акцентов** (статус, «С источниками», «Редактирование», «скоро», уровни риска в одном поле зрения).
5. **Навигация перегружена.** В сайдбаре одновременно: бренд, организация, глобальные разделы, раздел workspace, заблокированный пункт, настройки, свернуть, профиль. Дублируется хлебными крошками и заголовком страницы.
6. **Правая панель открыта по умолчанию на всех экранах** и сама содержит несколько секций, уменьшая рабочую область.
7. **Ответ AI содержит слишком много блоков сразу:** вывод, рекомендация, подтверждение, предположение, 3 действия, чипы контекста.
8. **Главная пытается показать всё**: заголовок, кнопку, список, быстрые действия, внимание и пустое состояние.

## 3. Принципы упрощения

- Один главный фокус на экран; вторичное скрыто за раскрытием или в панели.
- Один тип разделения: сначала пространство и фон, затем тонкая линия; рамки-карточки — только для интерактивных объектов и состояний.
- Бейджи — только для статуса документа/задачи и уровня риска; не использовать как декоративные метки.
- Минимальный размер текста 12px; основной интерфейс 13–14px; чтение документов 15–16px.
- Заглавные eyebrow-подписи — только в списках настроек/группах навигации; из заголовков страниц убрать.
- Правая панель закрыта по умолчанию и открывается по действию (источники, материалы, версии).
- Прототипные состояния вынесены из продукта в отдельный компактный «Демо-режим».

## 4. Изменения по уровням

### 4.1 Каркас и навигация

- Сайдбар: оставить бренд, переключатель организации (компактный), пункты верхнего уровня — Главная, Рабочие пространства, Настройки организации — и внутри выбранного workspace подменю Чаты / Документы / Исследования / Черновики. «Исследования» остаются в навигации (MVP по docs/00, 01, 20), но как спокойный недоступный пункт без бейджа «скоро»: подсказка «Экран не входит в первую итерацию».
- Профиль и «Свернуть» — одна нижняя строка.
- Убрать хлебные крошки из верхней панели; топбар оставить только с поиском и кнопкой панели. Название workspace и страницы показывать один раз — в заголовке.
- Глобальный поиск — иконка/короткое поле без хинта клавиш.
- Левая панель по умолчанию раскрыта, но визуально легче: без бордеров вокруг элементов, активный пункт — только фон.

### 4.2 Главная

Структура сверху вниз:
1. Короткое приветствие и одна основная кнопка «Новая задача».
2. **Недавние рабочие пространства** — основной блок, простой список без внешней рамки, 4–5 строк.
3. Справа/ниже одна компактная колонка «Требует внимания» (максимум 2 строки).
- Быстрые действия превратить в одну строку из 3 текстовых кнопок над списком или в меню «Новая задача»; отдельную сетку убрать.
- Пустое рабочее пространство вынести из главной в демо-режим и показывать в самом workspace.
- Баннер «все данные вымышлены» заменить постоянной небольшой пометкой «Демо-данные» в верхней панели (не прятать в подвал): документация требует не выдавать mock за реальную функциональность.

### 4.3 AI-чат

- Заголовок: только название диалога и контекст одной серой строкой; переключатель состояний убрать в демо-режим.
- Ответ структурировать в три видимых уровня, остальное сворачивается:
  1. **Вывод** — серифный заголовок и 1–2 абзаца.
  2. **Основания** — компактная строка с номерами ссылок и кнопкой «Источники (2)» для открытия панели.
  3. **Допущения** — одна спокойная строка/раскрывающийся блок.
- Рекомендуемую формулировку показывать как цитату внутри вывода, без отдельного блока с рамкой.
- Действия ответа: иконки Копировать / Изменить / Источники, подписи по hover; без текста на трёх кнопках.
- Композер: одна строка с прикреплённым документом внутри поля; предупреждение «ИИ может ошибаться» — одна короткая подпись.
- Правая панель закрыта, но над композером всегда видна компактная строка контекста: «Контекст: 1 документ · 2 источника · режим: выбранные документы» (docs/01: активный контекст должен быть понятен; docs/19: режим контекста). Клик открывает панель. Две вкладки: Источники и Материалы, недоступный документ — отдельной строкой внизу.
- Кнопка «Остановить» при генерации сохраняется и ведёт в состояние «Отменено».

### 4.4 Анализ документа

- Убрать переключатель состояний из экрана; состояния доступны через демо-режим.
- Двухколоночная схема «документ + риски» сохраняется. Список файлов уходит в выпадающий выбор документа в заголовке, но у каждого файла остаётся статус (загружен / обрабатывается / готов к анализу / ошибка). Полный список материалов со статусами и ошибками показывается во вкладке «Документы» workspace (docs/20, п. 9.4–9.5).
- Добавить однострочную панель ограничений анализа: например «Приложение 2 не обработано — анализ неполный» (docs/20, п. 6.7). Показывать только когда это применимо.
- Убрать «Страница 6 из 18» и любые номера страниц/абзацев, не заданные в данных: фиктивные координаты запрещены (docs/20, п. 6.6). Оставить только номера пунктов из текста демо-договора.
- Перед результатом кратко показать выбор типа анализа («Риски», «Обязательства», «Сроки») и кнопку запуска; кнопка недоступна, пока документ не в статусе «Готов к анализу» (docs/20, п. 6.2–6.3).
- Риски: компактные строки (уровень цветной точкой, название, пункт); развёрнутое описание только у выбранного риска.
- Сводка одним предложением: «1 высокий, 2 средних риска».
- Статус документа — одна метка в заголовке; процесс обработки — отдельный экран-состояние.
- Состояния загрузки/обработки/ошибки/нет доступа упростить: иконка, заголовок, одно предложение, одна основная кнопка.

### 4.5 Подготовка документа

- Верхняя строка: primary «Сохранить версию», вторичная «Копировать», меню «Ещё» с недоступным «Экспорт» (пометка «Не подключён в прототипе»; экспорт только по явному действию, docs/05).
- Панель инструментов редактора сократить до счётчика и кнопки «Уточнить с AI».
- AI-предложение показывать только при выделении/действии, как компактное сравнение рядом с текстом; вне действия — скрыто.
- Правая панель закрыта по умолчанию; содержит Структура / Версии / Основания в виде переключаемых вкладок. Под заголовком всегда остаётся одна строка «Проект. Требует проверки юристом» и ссылка на основания (docs/20, п. 7.5): это предупреждение не прячется в панель.
- Если есть несохранённые правки, принятие AI-предложения или «Новая редакция» требуют подтверждения (docs/05: правки не теряются без предупреждения).
- Бумагу документа сохранить, уменьшить внутренние отступы и серый фон вокруг.

### 4.6 Демо-режим

- Одна компактная кнопка «Состояния прототипа» внизу слева.
- Открывает список сценариев: пустое пространство, ожидание в очереди (queued), генерация (running), успех, ошибка с повтором (failed), отмена (cancelled), превышено время (timed_out), загрузка файла, обработка, ошибка обработки, нет доступа, ответ с источниками. Названия соответствуют статусам AIJob из D-011; статус `completed` для задач не использовать.
- Из интерфейса продукта убрать любые SegmentedControl, нужные только для показа состояний.

## 5. Дизайн-система: уточнения

- Шкала текста: 12 / 13 / 14 / 16 / 20 / 24. Документ — Noto Serif 15–16px.
- Отступы: 8 / 12 / 16 / 24 / 40; горизонтальные поля страницы 40px; ширина чтения 720–760px.
- Границы одного цвета, одной толщины; радиусы 6 и 10; без теней, кроме композера.
- Палитра: нейтральные поверхности, индиго только для главного действия, активной навигации и ссылок на источники. Красный/жёлтый — только для риска и ошибки.
- Иконки: 16/18px, один stroke; без иконок в каждой строке — только там, где они помогают распознать объект.
- Анимации: только раскрытие панели и появление состояния генерации.

## 6. Технический план реализации

1. Разделить `src/App.tsx` на файлы: `components/ui.tsx`, `components/shell.tsx`, `screens/*`, `data/demo.ts` (текущий один файл слишком плотный).
2. Пересобрать CSS: убрать избыточные классы, ввести переменные для шкалы текста, отступов и поверхностей.
3. Реализовать `DemoStatePanel` и общее состояние прототипа (screen + scenario).
4. Пересобрать Shell: правая панель закрыта по умолчанию, открывается из контента.
5. Переработать главную, чат, анализ и черновик по разделу 4.
6. Запустить `pnpm format` и `pnpm build`.
7. Проверить в preview: каждый экран на 1440×900 и 1180×800; фокус, сворачивание панелей, все состояния через демо-режим.

## 7. Критерии результата

- В первом экране видно не более одной основной группы контента + одной вторичной.
- Нет текста мельче 12px.
- На экране одновременно не более 3 видов цветных акцентов.
- В продукте нет элементов, существующих только для демонстрации, кроме одной кнопки демо-режима.
- Все ранее обещанные состояния по-прежнему достижимы.

Совместимо без изменений: четыре статуса документа, раздельные юридический вывод / источники / допущения, закрытый доступ без раскрытия названий недоступных документов, администратор без автоматического доступа, отсутствие полноценного редактора (20, п. 7.6), Client/Matter необязательны, только синтетические данные (D-012).

Не покрыто документами и остаётся открытым: статус «удаляется» (01 упоминает видимость удаления) — в первой итерации не показываем, предложить добавить позже; роль «Гость/внешний участник» — OPEN, в интерфейсе не рисуем.

## 9. Решения, которые нужно подтвердить

1. **Правая панель закрыта по умолчанию?** Рекомендация: да; открывать по действию. Альтернатива: оставить открытой только в анализе документа.
2. **Раздел «Исследования»:** по документации это MVP-раздел, поэтому убирать его нельзя. Рекомендация: оставить как недоступный пункт без бейджа.
3. **Демо-переключатель состояний:** плавающая кнопка внизу слева. Альтернатива: URL-параметр `?state=error` для разработки.
4. **Уровень плотности:** более воздушный (рекомендация) или плотный профессиональный.
