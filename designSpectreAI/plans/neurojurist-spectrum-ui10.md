# UI-10 — P0: выбранный scope, фрагменты и безопасность продолжения

Продолжение незавершённого пакета после UI-09 по поручению «поехали». Только синтетический UX/UI-макет: без backend, реального AI/RAG, чтения файлов и постоянного хранения. Исходные 174 ID и очередь HYP-01 сохранены.

## Выявленные пробелы и изменения

| Пробел | Реализованное поведение |
|---|---|
| Ручной выбор напрямую становился Sources used, даже без совпадений | `searchSelectedSamples` ищет только в выбранных версиях синтетического текста. Запрошенный набор хранится отдельно в `contextSources`; `sources` содержит только использованные совпадения |
| Ошибку поиска можно было показать только для workspace-scope | Сбой одной попытки доступен и для непустого ручного набора. Повтор использует исходный набор/версии, а не пустой список использованных источников |
| Панель источника всегда показывала один и тот же пункт | `sampleEvidence` выбирает совпавший абзац по вопросу. Переход открывает использованную версию; точные координаты в оригинале не обещаются |
| Вопрос PRIVATE-чата попадал в название общего Draft | Название «Черновик из ответа» нейтрально; диалог объясняет перенос только выбранного ответа и оснований, не PRIVATE-вопроса или всей переписки |
| Остановка при потере права выглядела пользовательской отменой до старта | У отмены есть причина `access`, отдельный заголовок и пояснение; нет автоматического возобновления или копирования неполученного результата |

### Ручной scope и восстановление

- Несовпавший выбранный документ не считается использованным и не заменяется подходящим документом вне выбора.
- При отсутствии совпадений показано «Подходящих фрагментов не найдено», без выдуманных цитат, копирования и создания Draft. Это не доказательство отсутствия условия.
- При совпадении только части набора есть предупреждение «Не весь выбранный набор дал совпадения»; оно переносится в копию и исходный текст Draft. Полнота извлечения учитывается отдельно для реально использованных версий.
- Сбой retrieval не маскируется как пустая выдача. Старую неудачную попытку можно открыть после успешного повтора в отдельной ветке.
- Исторический повтор сохраняет выбранную редакцию. Обычный следующий вопрос требует явного обновления устаревшего выбора; старый ответ сохраняет старую версию.
- «Изменить вопрос» восстанавливает вопрос даже при удалённом выбранном документе. Затем можно явно убрать недоступный материал и выбрать замену; вопрос не теряется.
- Существующий доступный Research-контекст не объявляется отсутствующим только из-за пустой документальной выдачи; основание различается явно.

### Доступ и задачи — проверенные границы

- Удаление использованного источника во время/после генерации закрывает зависимый ответ и производный Draft. Внутренний технический статус задачи может стать succeeded, но это не право открыть закрытый результат.
- Удаление выбранного, но не использованного документа не превращает его в основание старого ответа. Следующий запрос требует исправить сохранённый scope.
- VIEWER не отправляет/повторяет запрос и не редактирует его для нового запуска. PRIVATE-диалог не открывается другому участнику при доступном ему производном Draft.
- Потеря actor-права во время running приводит к явной остановке; переключение демоперсоны само по себе не отменяет задачу другого сотрудника.
- Выход/вход **без перезагрузки вкладки** ведёт на Главную и позволяет вернуться к той же задаче без дублирования. После reload синтетические данные сбрасываются, старая ссылка закрывается. Это **не реализация полного JOB-07** с закрытием браузера и durable-восстановлением.

## Воспроизведение в preview

1. В новом Chat выбрать готовый документ и спросить «Квазикристаллическая телепортация»: нет совпадений/цитат/Draft. Затем «Неустойка»: выбранный набор сохранён, использованный источник появился.
2. Добавить полный и частично извлечённый образцы. Выбрать оба, спросить «Убытков»: используется только полный образец; ограничение покрытия видно в ответе/копии. В источнике — п. 5.2 и правильная версия.
3. В ручном scope включить сбой одной попытки → отправить → повторить поиск. Старая попытка остаётся, успешная ветка использует исходный выбранный набор. При удалённом выборе сначала «Изменить вопрос», затем явное исправление материалов.
4. Из PRIVATE-чата создать Draft → переключить демоперсону на участника с доступом к проекту: Draft имеет нейтральное название, PRIVATE-диалог недоступен.
5. Во время задачи изменить роль инициатора на VIEWER от имени OWNER: показана причина остановки, запуск/копирование/создание Draft запрещены.
