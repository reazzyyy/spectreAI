# Потоки данных и инвентаризация

**Статус: PROPOSED**

Для каждого потока заполнить запись со следующими полями:

| Поле | Что указать |
|---|---|
| ID потока | Уникальный идентификатор |
| Источник → получатель | Компоненты и внешние стороны |
| Цель | Зачем передаются данные |
| Категории данных | По `data-classification.md` |
| Хранилище/регион | Фактическая площадка и страна |
| Транспорт | Протокол и защита канала |
| Доступ | Сервисные и пользовательские роли |
| Срок хранения | Основание и срок |
| Удаление | Как удаляются активные и производные копии |
| Подтверждение | Тест, конфигурация или договор |

## Обязательные потоки для инвентаризации
- Браузер → Web-приложение → API.
- API → PostgreSQL.
- API → файловое хранилище.
- API → Redis/BullMQ → worker.
- Worker → извлечение текста/OCR.
- Worker → полнотекстовый и векторный индексы.
- AI Gateway → `SyntheticAIProvider`.
- Журналы и метрики → система мониторинга.
- База/файлы → резервное копирование.
- Экспорт и скачивание документа пользователем.

## Требования
- Не считать регион размещения подтверждённым только по плану: зафиксировать фактическую конфигурацию и договор поставщика.
- Не добавлять внешнего получателя в production без оценки данных, договора, региона и правового основания.
- Для каждого производного набора данных указать источник, ACL-модель и способ удаления.
