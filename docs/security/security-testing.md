# Проверки безопасности и критерии приёмки

**Статус: PROPOSED**

**Канон стратегии тестов:** `docs/22-testing-and-quality-strategy.md`. Ниже — security checklist; при конфликте приоритет у канона и `docs/decisions-log.md`.

| Область | Минимальная проверка | Критерий |
|---|---|---|
| Auth | Неаутентифицированный запрос к защищённому API | 401/403, без данных |
| Tenant isolation | Пользователь A запрашивает объект организации B | Доступ запрещён |
| BOLA/IDOR | Подмена ID файла, workspace, matter, job | Нет раскрытия/изменения |
| Search/RAG | Запрос с доступом только к части документов | В ответе только разрешённые данные |
| Download/export | Прямая ссылка или повтор старого URL | Проверка прав на сервере |
| Background jobs | Подмена job ID / отзыв членства | Результат не раскрывается |
| Admin content grant | Нет одобрения, self-approval, истёкший grant | Доступ запрещён |
| Deletion | Удаление документа и производных копий | Все активные копии удалены в целевой срок |
| AI provider | Внешний вызов до O-002 | Только синтетические данные |
| Logging | Ошибки API/worker | Нет полного контента и секретов |
| Upload | Неподдерживаемый тип, превышение размера, архив/макрос | Отклонение безопасным способом |
| SSRF | URL на localhost/private IP/metadata endpoint | Запрос заблокирован |
| XSS/CSRF | Враждебное содержимое и межсайтовый запрос | Нет исполнения/несанкционированного действия |

Для каждой проверки хранить дату, версию/commit, тестовый сценарий, результат, дефект и ссылку на CI или протокол. Не маркировать контроль `verified`, если тест не выполнялся.
