# Классификация данных

**Статус: PROPOSED** (operational mapping; не заменяет канон)

## Нормативная шкала

Единственная нормативная внутренняя классификация проекта — **D0–D4** в [`docs/03-data-security.md`](../03-data-security.md):

| Код | Смысл (канон) |
|---|---|
| **D0** | Публичные правовые материалы |
| **D1** | Данные аккаунта и членства |
| **D2** | Метаданные клиентов и дел |
| **D3** | Содержимое договоров, исков, переписки, вложений и OCR |
| **D4** | Секреты безопасности — пароли, токены, ключи |

Это внутренняя классификация проекта, не официальная юридическая классификация. В спецификациях, коде, тестах, аудите и evidence использовать **только коды D0–D4**.

## Соответствие черновых кодов C0–C4

Коды **C0–C4** ниже — черновая шкала из ранней версии security-пакета. Они **не являются отдельной нормативной классификацией** и не должны вводиться в API, схему данных или новые документы как самостоятельные уровни. При чтении старых черновиков переводить в D* по таблице; при неоднозначности — уточнять по смыслу канона D0–D4 и запрашивать решение.

| Черновой код C* | Ближайший нормативный D* | Примечание о несовпадении 1:1 |
|---|---|---|
| **C0** публичные | **D0** | Согласовано по смыслу публичных материалов |
| **C1** внутренние инструкции / техсведения без клиентского содержимого | **D1** (частично) или вне шкалы контента | У D1 в каноне — аккаунт и членство, не «внутренние инструкции». Внутренние runbook без клиентских данных ближе к D1 по чувствительности доступа, но не смешивать с membership-данными без явной пометки |
| **C2** рабочие данные org, настройки, метаданные workspace | **D2** (частично) | У D2 — метаданные клиентов и дел; настройки org/workspace могут быть D1/D2 по контексту — не повышать до D3 без содержимого |
| **C3** юридически чувствительные (документы, дело, переписка, OCR, embeddings, AI-контекст) | **D3** | Производные (OCR, embeddings, summaries, caches, prompts с содержимым) — как минимум **D3** |
| **C4** секреты доступа | **D4** | Согласовано |

## Минимальные правила (в терминах D*)

- **D3** не отправлять во внешние AI-системы до закрытия **O-002**; до этого — только `SyntheticAIProvider` и синтетические данные (**D-012**).
- **D4** никогда не помещать в обычные логи, тикеты, исходный код или документы с широким доступом.
- Доступ к **D3** — только по необходимости и с серверной проверкой прав.
- Производные представления **D3** (OCR, embeddings, summaries, кеши, prompts) считать как минимум **D3**.
- Синтетические данные должны быть явно маркированы и не содержать реальных клиентских сведений.
