# Обзор безопасности

**Статус: PROPOSED**

Пакет дополняет каноны (`03`, `07`, `08`, `09`, `14`, `22`, `23`, `25`); не заменяет их. Приоритет: `docs/decisions-log.md` → канон области → этот каталог. Классификация данных — **D0–D4** (`docs/03-data-security.md`).

## Цель
Определить минимальный набор организационных и технических требований безопасности для MVP «НейроЮрист Спектр».

## Область
Приложение Next.js, API NestJS, PostgreSQL, Prisma, Redis/BullMQ, объектное/файловое хранилище, поиск и векторные индексы, фоновые задачи, AI Gateway, журналы и резервные копии.

## Обязательные принципы
1. Проверять аутентификацию, членство в организации и права на конкретный объект на сервере при каждой операции.
2. Применять изоляцию данных организаций ко всем данным, индексам, кешам, очередям, поисковым результатам, выгрузкам и AI-контексту. (Архитектурный ярлык multi-tenant остаётся **H-001** и этим пакетом не повышается до CONFIRMED; требования изоляции для реализации и тестов обязательны.)
3. Не считать скрытие элемента интерфейса контролем доступа.
4. Не передавать реальные юридические документы внешнему AI до закрытия решения O-002 и проверки применимых условий.
5. Использовать `SyntheticAIProvider` и синтетические данные до такого разрешения (**D-012**).
6. Не логировать полные документы, prompts/responses, пароли, токены, cookies и секреты.
7. Удаление должно охватывать исходные и производные данные, индексы, кеши, очереди и процесс повторного применения удаления после восстановления резервной копии (**D-019**, **D-020**).
8. Не включать обходные режимы доступа без отдельного решения и документированного контроля.

## Статус контроля
Для каждого требования фиксировать: `not_implemented`, `implemented_not_verified`, `verified`, `not_applicable`. Статус `verified` допускается только при наличии воспроизводимого свидетельства: теста, конфигурации, протокола проверки или записи об успешном восстановлении.
