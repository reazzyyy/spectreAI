# 02. Архитектура

Статус: базовый стек MVP **CONFIRMED** (D-008); отдельные эксплуатационные параметры остаются открытыми.

## Цели
Изоляция организаций, контролируемый поток данных, асинхронная обработка файлов, заменяемые LLM-провайдеры и возможность будущего self-hosting.

## Логические компоненты
1. Web UI.
2. Backend API: аутентификация, авторизация, бизнес-правила.
3. Реляционная БД: пользователи, организации, права, метаданные, чаты и версии.
4. Приватное объектное хранилище: оригиналы и производные файлы.
5. Очередь фоновых задач.
6. Document processing: проверка, извлечение, OCR, нормализация.
7. Search/RAG: только доступные текущему пользователю материалы.
8. LLM gateway: адаптеры, политика передачи, лимиты, тайм-ауты и учёт стоимости. Целевой внешний — OpenAI API (**D-015**); до **O-002** — только **SyntheticAIProvider** (**D-012**).
9. Аудит и наблюдаемость.
10. Планировщик очистки и повторных задач.

## Подтверждённый стек MVP — D-008
- Frontend: Next.js.
- Backend API: NestJS.
- Основная БД: PostgreSQL.
- ORM: Prisma.
- Очереди и фоновые задачи: Redis + BullMQ.
- Векторный поиск: PostgreSQL + `pgvector` вместе с полнотекстовым поиском (D-018).

Конкретный хостинг-провайдер и эксплуатационные параметры не считаются выбранными только на основании этого списка.

## Границы доверия
Браузер, внешний LLM-провайдер, парсер/OCR, очередь, индекс, кэш и логи — отдельные поверхности риска. Администратор сервиса не должен автоматически получать неограниченный доступ к содержимому дел.

## Поток AI-запроса
Аутентификация → проверка организации и разрешений → выбор разрешённого контекста → поиск разрешённых фрагментов (**D-018**) → проверка политики передачи → вызов через gateway (**Synthetic до O-002**; OpenAI только после закрытия O-002) → проверка результата и источников → сохранение и выдача ответа → учёт использования без записи полного текста в обычные логи. UI помечает synthetic/test режим, пока действует D-012.

## API
Предлагается версионированный API, серверная валидация, единый безопасный формат ошибок, лимиты размера, авторизация каждого объекта, идемпотентность для повторяемых операций и тестируемые контракты.

## Фоновые задачи
Подтверждённые статусы AIJob (D-011): `queued`, `running`, `succeeded`, `failed`, `cancelled`, `timed_out`. Нужны ограниченные ретраи, backoff, идемпотентность, корреляция и лимиты. Повторная задача не должна бесконтрольно дублировать расходы.

## Эксплуатация
Подтверждённые цели эксплуатации: инфраструктура в РФ (D-014), резервные копии хранятся 35 дней (D-020), RPO ≤ 24 ч и RTO ≤ 8 ч (D-022). Конкретный провайдер, runbook, нагрузочные лимиты и подтверждение восстановления остаются задачами до production.

## Self-hosting
Вызовы идут через внутренний контракт. Локальная модель не бесплатна: нужно учитывать вычислительные ресурсы, память, хранение, обновления, мониторинг и поддержку.
