# Статусы документов и канонические источники

**Статус:** CONFIRMED как правило работы с документацией; содержательные архитектурные предложения в перечисленных ниже документах не становятся автоматически утверждёнными. Решения **D-008–D-022** в `docs/decisions-log.md` имеют приоритет над предложенными параметрами в спецификациях.

## 1. Приоритет источников

Приоритет при работе Cursor:

1. `AGENTS.md` и применимые `.cursor/rules/` — правила выполнения задач и запреты.
2. `docs/decisions-log.md` — статус продуктовых решений (включая **D-008–D-022**).
3. Каноническая спецификация соответствующей области из таблицы ниже.
4. `docs/security/` — **PROPOSED** security governance (дополнение; не заменяет п. 2–3).
5. Текущая задача и явные уточнения владельца продукта.
6. Примеры, комментарии и предположения в коде.

Для содержательных требований безопасности при конфликте внутри документации: **`docs/decisions-log.md` → канон области → `docs/security/`**. Пакет `docs/security/` не подтверждает реализацию контролей и не повышает `PROPOSED`/`OPEN`/`HYPOTHESIS` до `CONFIRMED`.

Этот список не разрешает конфликт между подтверждёнными требованиями. Если источники противоречат друг другу, Cursor должен остановить затронутую часть работы, описать варианты и запросить решение.

## 3.1. Пакет `docs/security/` (PROPOSED)

Каталог `docs/security/` — предложенное дополнение по security governance (классификация/mapping, потоки данных, encryption evidence, privileged access summary, subprocessors, vulnerability management, incident response, BCDR, AI risk, security testing checklist, evidence registry).

Ограничения:

- не заменяет каноны областей из таблицы §2;
- не считается доказательством, что контроли реализованы или прошли аудит;
- статус контроля `verified` допустим только при воспроизводимом свидетельстве (см. `security/security-evidence.md`);
- нормативная шкала данных — **D0–D4** (`03-data-security.md`); коды C0–C4 не нормативны;
- до закрытия **O-002** реальные клиентские документы во внешний AI не передаются — только `SyntheticAIProvider` (**D-012**).

Сверка пакета с каноном: `security/CONTRADICTIONS-AND-INTEGRATION-PLAN.md`. Открытые operational-вопросы: `security/DECISIONS-TO-REVIEW.md`.

## 4. Значение статусов

- **CONFIRMED / ACCEPTED** — решение явно утверждено владельцем продукта.
- **PROPOSED / Proposed** — предложение; требует согласования перед реализацией, если влияет на архитектуру, безопасность, данные или внешние интеграции.
- **OPEN** — решения нет.
- **HYPOTHESIS** — предположение для проверки.
- **ARCHIVED / NON-NORMATIVE** — история/материал для сверки, не нормативный источник.

Если статус отсутствует или неоднозначен, не повышать его самостоятельно. Спросить владельца продукта или явно вынести решение на согласование.

## 5. Минимальный процесс изменения документации

1. Перед изменением прочитать канонический документ и связанные решения.
2. В начале задачи перечислить затрагиваемые документы, компоненты и риски.
3. Не менять утверждённые решения без явного разрешения.
4. Если принято новое решение — обновить журнал, документы и тестовые критерии в одном изменении.
5. Перед завершением проверить относительные ссылки, упоминания переименованных файлов и статус изменённых документов.
6. В отчёте отделить сделанные изменения от непроверенных предположений и реально выполненных тестов.
7. При изменении исполняемого кода — соблюдать обязательную документацию кода (`.cursor/rules/07-code-documentation.mdc`): обновить AS-IS (`26-codebase-current-state.md`) и README затронутого пакета/приложения в том же изменении; не описывать целевое MVP как уже существующее в коде.
