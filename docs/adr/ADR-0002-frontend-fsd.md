# ADR-0002: Feature-Sliced Design для frontend

Статус: **CONFIRMED** по журналу (**D-023**). Дата: 2026-10-30.

## Контекст

`@spectre/web` растёт от shell и login к workspace, чату, документам и черновикам. Без единой методологии слоёв логика UI, API-клиента и сценариев смешивается в `app/` и ad-hoc папках, что усложняет границы ответственности и работу агентов/разработчиков. В `docs/21-frontend-architecture.md` FSD уже описывался как ориентир (**FE-001** OPEN).

## Решение

1. Обязательная архитектура frontend — **Feature-Sliced Design (FSD)** в `apps/web`.
2. Нормативные слои и направление импортов:  
   `app → widgets → features → entities → shared`.
3. Правила импортов из `docs/21` §4.1 — нормативные (не «на усмотрение»):
   - `shared` не импортирует `entities` / `features` / `widgets` / `app`;
   - `entities` не импортирует `features` / `widgets`;
   - `features` не импортирует `widgets`;
   - `widgets` не импортирует страницы `app`;
   - без скрытых циклов между модулями одного слоя;
   - публичный API слайса — через `index.ts`, только если это реально ограничивает импорты.
4. Папки слоёв создаются по мере появления функциональности, а не заранее «ради шаблона».
5. Next.js App Router остаётся в `src/app` (слой `app` в терминах FSD): маршруты композируют widgets/features, не содержат бизнес-логики, которую можно вынести ниже.
6. Backend остаётся источником истины по правам (**D-008** стек не меняется этим ADR).

## Альтернативы

### Плоская структура `components/` + `hooks/`
- Плюсы: проще на старте.
- Минусы: нет стабильных границ при росте фич; смешение сущностей и сценариев.
- Отклонено: не масштабируется под MVP-области chat/docs/research/drafts/workspace.

### Только «pages + shared»
- Плюсы: меньше слоёв.
- Минусы: features и entities неизбежно окажутся в shared или pages.
- Отклонено: дублирует проблемы плоской структуры.

## Последствия

- Новые изменения в `apps/web` размещаются в FSD-слоях; код вне слоёв (кроме служебного Next) не вводится.
- Текущий scaffold login (частично `shared/api` + файлы рядом с `app`) подлежит выравниванию под FSD в ближайшем срезе — AS-IS не подменяет **D-023**.
- Границы слоёв проверяются **Steiger** (`@feature-sliced/steiger-plugin`) + ESLint `no-restricted-imports` в `apps/web` (`lint` / `lint:fsd`). Инструмент зафиксирован в AS-IS; набор правил можно уточнять в `steiger.config.ts` без отмены **D-023**.
- FE-001 в `docs/21` закрывается этим решением; FE-002+ остаются OPEN.
