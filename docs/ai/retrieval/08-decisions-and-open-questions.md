# Retrieval — решения, гипотезы и открытые вопросы

**Статус:** PROPOSED  
**Версия:** 0.1

## 1. Подтверждённый контекст проекта

Ниже приведён контекст, известный из ранее согласованных обсуждений. Сверять только с актуальным `docs/decisions-log.md`; этот файл не является источником официального статуса D/O. Сверка интеграции пакета: `INTEGRATION-NOTES.md`.

- PostgreSQL выбран для основной БД.
- pgvector выбран как направление для векторного поиска (ранее отмечено D-018).
- Для MVP используется SyntheticAIProvider до закрытия применимых compliance gates.
- Реальные клиентские документы нельзя отправлять во внешние AI API до закрытия соответствующих требований.
- Для пользовательских данных обязательны серверная авторизация, изоляция tenant/workspace и RLS в MVP.

## 2. Предварительные технические гипотезы

| Область | Гипотеза | Статус |
|---|---|---|
| Lexical search | Сравнить PostgreSQL FTS и ParadeDB BM25 | TO_VALIDATE |
| Embeddings | Qwen3-Embedding как кандидат | TO_VALIDATE |
| Vector index | HNSW; exact search как baseline на малых корпусах | TO_VALIDATE |
| Fusion | RRF | PROPOSED |
| Reranking | Cross-Encoder только при доказанной пользе | DEFERRED |
| Chunking | Structure-Aware, ограниченный Parent-Child | PROPOSED |
| Collections | Логические области знаний в общей архитектуре | PROPOSED |
| OCR | По необходимости для сканов | PROPOSED |
| Graph DB | Не включать в MVP | DEFERRED |
| Semantic chunking | Не включать в MVP | DEFERRED |
| Blue-green index deployment | Отложить до доказанной потребности | DEFERRED |

Этот документ не меняет статусы D/O/H, не назначает новые официальные идентификаторы и не закрывает вопросы. Когда вопрос требует решения владельца, он должен быть перенесён в действующий процесс управления решениями проекта после проверки отсутствия дубликата.

## 5. Следующий этап

Приоритетная последовательность:
1. выбрать разрешённый тестовый нормативный источник;
2. взять один акт с историческими изменениями;
3. проверить временную модель на нескольких изменённых положениях;
4. определить минимальный контракт parser output;
5. реализовать/смоделировать exact lookup;
6. собрать эталонные запросы;
7. затем сравнить FTS и vector retrieval.
