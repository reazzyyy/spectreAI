# Сверка Retrieval Engine v0.2 с каноном

**Статус:** WORKING / сверка при повторной интеграции (2026-11-16)  
**Назначение:** границы чтения версии 0.2. Не повышает PROPOSED до CONFIRMED.

## 1. Жёсткого конфликта со статусами D/O/H нет

v0.2 явно оставляет временную модель `PROPOSED / TO_VALIDATE` и запрещает считать TypeScript-контракт схемой Prisma.

## 2. Зоны внимания, добавленные в 0.2

### 2.1. Официальные реквизиты в T-01–T-03

Кейсы называют конкретные федеральные законы и статьи. Это не разрешение обходить **O-006**:

- не скачивать и не индексировать официальные тексты в рамках этой документации;
- не объявлять кейсы приёмочными, пока формулировки не сверены с актуальной редакцией (сам `09` это требует);
- синтетические факты в T-03 допустимы; корпус норм — нет, пока источник не разрешён.

### 2.2. ApplicabilityRule не является движком права

Контракт ограничен `ALL` и тремя типами условий. Сложный текст закона → `manual_review` плюс исходный текст и locator. Не реализовывать интерпретатор произвольных норм «по образцу интерфейса».

### 2.3. Три компонента ≠ три таблицы

`LegalProvisionTextVersion`, `AmendmentOperation`, `ApplicabilityRule` можно позже выразить меньшим числом таблиц, если сохраняются аудит и разделение дат (действие текста, период правоотношений, контрольная дата факта, recorded time). До O-006 схему не фиксировать.

### 2.4. Порядок работ

v0.2 ставит exact lookup с временным контекстом раньше benchmark FTS/vector. Для **нормативного** корпуса это ждёт O-006. Phase 6 user-document FTS (`docs/33`) этим не отменяется и не смешивается с LegalAct*.

### 2.5. Прежние границы 0.1 сохраняются

ParadeDB — только эксперимент поверх **D-018**. Embedding dimensions — Gate B. OCR клиентских сканов — **D-031** / **O-004**. Реальные документы во внешний AI — **O-002** / **D-012**.

## 3. План после решений владельца

1. Юридическая сверка T-01–T-03 (scope части 77 ст. 112 44-ФЗ, предметные границы 611-ФЗ, контрольная дата 347-ФЗ).
2. Закрытие или сужение **O-006** для тестового источника.
3. Минимальный parser output: locator + temporal metadata, без Rule Engine.
4. Только затем exact lookup на одном акте.
5. Параллельно и без ожидания п. 1–4: Phase 6A по своим документам.
