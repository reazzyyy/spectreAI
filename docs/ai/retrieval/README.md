## Правила чтения

- `CONFIRMED` означает только то, что уже подтверждено в контексте проекта.
- `PROPOSED` — предлагаемое направление, которое ещё нужно согласовать.
- `OPEN` — вопрос не закрыт; документ не должен трактоваться как решение.
- `TO_VALIDATE` — гипотеза, которую нужно проверить на данных или прототипе.
- Этот пакет не заменяет `decisions-log.md`, канонические документы проекта, security-документацию или ADR.
- Не менять статусы D/O/H и не создавать новые официальные ID без отдельного согласования.
- Не считать описанные компоненты реализованными.

## Важные ограничения проекта

- До закрытия применимых compliance/data-transfer gates использовать только `SyntheticAIProvider` и синтетические данные для AI-обработки. Не отправлять реальные клиентские документы во внешние AI API.
- Инфраструктура приложения, primary DB и файловое хранилище для production должны соответствовать действующим требованиям проекта по размещению данных в РФ.
- Источники нормативных актов и судебной практики должны использоваться с учётом условий доступа, лицензий и допустимого способа обработки.
- Поисковая релевантность не равна юридической применимости. Дата действия, переходные положения, юрисдикция и контекст должны проверяться отдельно.
- Временная модель в версии 0.2 остаётся `PROPOSED`: она проверена на трёх показательных примерах, но не доказана для всех видов переходных положений российского законодательства.
- `ApplicabilityRule`, `AmendmentOperation` и `LegalProvisionTextVersion` — логические компоненты. Их наличие не означает обязательного создания трёх отдельных таблиц Prisma.

## Изменения версии 0.2

- Зафиксировано разделение истории текста нормы, операций изменения и правил применимости.
- Уточнён временной контракт: effective time, период охватываемых правоотношений, контрольная дата фактов и recorded time не смешиваются.
- Добавлены ограничения MVP для структурированных условий применимости.
- Добавлены три временных тест-кейса и требование различать `unknown`, `true` и `false`.
- Статусы официальных D/O/H не менялись; временная модель остаётся `PROPOSED`.

## Как обновлять пакет

Перед внесением изменений сверить:
1. актуальный `decisions-log.md`;
2. канонические документы архитектуры и безопасности;
3. существующие схемы Prisma и API-контракты;
4. текущую структуру `docs/`, чтобы избежать дублирования.

Если документ расходится с каноническим решением, приоритет имеет действующая иерархия документации проекта, а конфликт необходимо вынести на согласование.
