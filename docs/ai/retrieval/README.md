## Правила чтения

- `CONFIRMED` означает только то, что уже подтверждено в контексте проекта.
- `PROPOSED` — предлагаемое направление, которое ещё нужно согласовать.
- `OPEN` — вопрос не закрыт; документ не должен трактоваться как решение.
- `TO_VALIDATE` — гипотеза, которую нужно проверить на данных или прототипе.
- Этот пакет не заменяет `decisions-log.md`, канонические документы проекта, security-документацию или ADR.
- Не менять статусы D/O/H и не создавать новые официальные ID без отдельного согласования.
- Не считать описанные компоненты реализованными.

## Важные ограничения проекта

- До закрытия применимых compliance/data-transfer gates использовать только `SyntheticAIProvider` и синтетические данные для AI-обработки. Не отправлять реальные клиентские документы во внешние AI API (**D-012** / **O-002**).
- Инфраструктура приложения, primary DB и файловое хранилище для production должны соответствовать действующим требованиям проекта по размещению данных в РФ (**D-014**).
- Источники нормативных актов и судебной практики — только после **O-006** (лицензии / способ получения).
- Поисковая релевантность не равна юридической применимости. Дата действия, переходные положения, юрисдикция и контекст должны проверяться отдельно.
- PostgreSQL FTS + pgvector — **D-018**; ParadeDB и конкретная embedding-модель остаются кандидатами до отдельного решения / Gate B.

## Как обновлять пакет

Перед внесением изменений сверить:
1. актуальный `decisions-log.md`;
2. канонические документы архитектуры и безопасности;
3. существующие схемы Prisma и API-контракты;
4. текущую структуру `docs/`, чтобы избежать дублирования.

Если документ расходится с каноническим решением, приоритет имеет действующая иерархия документации проекта, а конфликт необходимо вынести на согласование.
