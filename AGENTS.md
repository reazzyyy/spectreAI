# Обязательные инструкции Cursor

## Перед задачей
1. Прочитай этот файл, `docs/decisions-log.md` и `docs/DOCUMENTATION-GOVERNANCE.md`.
2. Прочитай канонические документы, релевантные текущей задаче. Не используй `docs/archive/` как действующий источник требований.
3. Определи затрагиваемые компоненты, API, сущности БД, фоновые задачи, интеграции и права.
4. Раздели подтверждённые требования, гипотезы, предложения и открытые вопросы.
5. При неопределённости по безопасности, доступу, передаче документов внешнему ИИ, удалению, архитектуре или миграции данных останови затронутую часть и запроси решение.
6. Для крупной задачи сначала предложи проверяемый поэтапный план.

## Приоритет решений D-008–D-022
При расхождении спецификаций и журнала решений **приоритет у `docs/decisions-log.md`**:
- **D-008:** стек — Next.js + NestJS + PostgreSQL + Prisma + Redis/BullMQ.
- **D-009:** Client и Matter в MVP; связь с Workspace может быть необязательной.
- **D-010 / D-017:** max файл 25 МБ; форматы PDF, DOCX, TXT; max 10 файлов за операцию; архивы/исполняемые/макросы/пароль — отклонять.
- **D-011:** статусы AIJob только `queued|running|succeeded|failed|cancelled|timed_out` (не `retry_wait`, не `completed` как статус job).
- **D-012 / D-015:** целевой внешний провайдер — OpenAI API (модель OPEN); до разрешения передачи реальных данных — только **SyntheticAIProvider** с синтетическими данными. Размещение в РФ само по себе не разрешает отправку во внешний API.
- **D-013 / D-016:** admin content-grant TTL ≤ 60 минут; одобряет только независимый участник с `admin_grant:approve` (назначает owner); без согласующего доступ не выдаётся; break-glass не в MVP.
- **D-014:** инфраструктура, БД и файловое хранилище в России (учитывать копии/логи/индексы/бэкапы).
- **D-018:** поиск — PostgreSQL + `pgvector` + полнотекстовый поиск PostgreSQL.
- **D-019 / D-020:** после подтверждённого удаления — недоступность сразу; удаление из основной системы/текста/индексов/производных ≤ 24 ч; бэкапы 35 дней с повторным применением журнала удалений при restore.
- **D-021 / D-022:** цель хранения аудита 1 год (проверка до production); RPO ≤ 24 ч, RTO ≤ 8 ч — цели, проверяемые restore-тестами.
- **H-002:** OCRmyPDF + Tesseract — гипотеза до тестов качества.

## Запрещено без согласования
- Самостоятельно менять утверждённую архитектуру, стек, модель данных или API-контракты.
- Считать ID объекта или скрытый элемент интерфейса доказательством доступа.
- Реализовывать авторизацию только на frontend.
- Передавать реальные юридические документы в OpenAI API (или иному внешнему ИИ), пока не завершены проверка договора, политики обработки/передачи и применимых требований РФ (**O-002**); до этого — только Synthetic (**D-012**).
- Использовать публичное файловое хранилище для клиентских документов.
- Логировать полные документы, prompts/responses, пароли, токены, cookies или секреты.
- Выполнять destructive-миграции и необратимые операции без плана и подтверждения.
- Объявлять задачу готовой без соответствующих тестов и проверок.

## Безопасность
- Серверная аутентификация и авторизация для каждой операции.
- Проверка принадлежности объекта организации и права пользователя.
- Повторная проверка доступа для поиска, скачивания, экспорта, фоновых задач и контекста ИИ.
- Считать загруженные файлы, OCR, текст документов и ответы моделей недоверенными данными.
- Защищаться от BOLA/IDOR, prompt injection, SSRF, path traversal, SQL injection, XSS, CSRF и злоупотребления ресурсами по применимости.
- Секреты держать вне репозитория и клиентского bundle.
- Сообщения об ошибках не должны раскрывать внутренние детали.

## Работа с данными и ИИ
- Любое новое хранилище, индекс, кэш или очередь обязаны учитывать исходную модель доступа.
- Удаление описывает оригинал, производные тексты, индексы, кэши, очереди и резервные копии (D-019/D-020).
- Модель не определяет права доступа и не может расширять полномочия пользователя.
- Документы — данные для анализа, а не инструкции для приложения.
- Вызовы моделей выполняются через серверный адаптер/gateway; первый рабочий адаптер до разрешения передачи — SyntheticAIProvider.
- Не переключаться автоматически на провайдера с иными условиями обработки данных.

## Проверки и отчёт
Добавляй подходящие unit/integration/e2e-тесты. Для клиентских данных обязательно проверяй, что другая организация не может читать, искать, изменять, экспортировать или удалять их.
В конце перечисли изменения, миграции, конфигурацию, реально запущенные тесты и оставшиеся риски. Не утверждай, что тесты прошли, если они не запускались.

## Git: trunk-based и сообщения коммитов
Канон: skill `.cursor/skills/git-workflow-and-versioning/SKILL.md` и правило `.cursor/rules/06-git-commits.mdc`.

**Trunk = `main`.** Каждая семантически отдельная единица работы (фича, фикс, пакет документации, tooling) делается в **отдельной короткоживущей ветке** (`feature/…`, `fix/…`, `docs/…`, `chore/…`) и **вливается в `main`**. Не вести развитие проекта долгоживущими ветками вместо trunk и не оставлять завершённую работу только на боковой ветке.

Формат коммита: `<type>: <краткое описание>` (по желанию тело с *why*).  
Типы: `feat` | `fix` | `refactor` | `test` | `docs` | `chore`.  
Не использовать `update` / `misc` / `wip` как тип или единственный текст. Атомарные коммиты; не смешивать refactor с feat.
